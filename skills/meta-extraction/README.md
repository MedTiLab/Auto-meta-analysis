# meta-extraction skill — short README

This is a Claude agent skill, not a Python framework. The agent reads
`SKILL.md` as its procedure and the per-type files under `templates/` as the
field-by-field extraction rules. The only executable code in the skill is a
single numeric-sanity validator (`scripts/validate_estimates.py`), which the
agent calls *after* it has written candidate rows.

## File layout

```
.claude/skills/meta-extraction/
├── SKILL.md                              # the agent's procedure
├── README.md                             # this file
├── templates/
│   ├── 00_paper_type_router.md           # classify the paper into Meta type(s)
│   ├── 01_study_metadata.md              # always-on metadata (join key)
│   ├── 02_rct_binary.md                  # RCT, binary outcome (2x2 + RR/OR/RD)
│   ├── 03_rct_continuous.md              # RCT, continuous outcome (mean/SD/MD/SMD)
│   ├── 04_observational_or_rr.md         # cohort / case-control / cross-sectional
│   ├── 05_prognostic_hr.md               # survival HR (OS/PFS/DFS/RFS/EFS)
│   ├── 06_diagnostic_dta.md              # DTA; bridges to diagnostic-data-extraction
│   ├── 07_prevalence_single_arm.md       # prevalence / single-arm rate
│   └── 08_dose_response.md               # categorical or per-unit exposure
├── checklists/
│   ├── effect_size_sanity.md             # numeric consistency rules
│   └── conflict_priority.md              # abstract vs body vs table priority
├── output_schemas/
│   └── tidy_estimates.schema.md          # canonical CSV column reference
├── scripts/
│   └── validate_estimates.py             # stdlib-only numeric validator
└── examples/
    ├── example_candidates.jsonl          # tiny realistic input
    ├── example_tidy_estimates.csv        # regenerated by the validator
    ├── example_validation_report.md      # regenerated by the validator
    ├── by_type/                          # per-type CSVs (regenerated)
    └── example_walkthrough.md            # walk one real paper end-to-end
```

## Where the skill writes its outputs in a real project

```
05_data_extraction/extraction_candidates.jsonl   # agent appends rows here
05_data_extraction/extraction_review.csv         # human-review queue
05_data_extraction/extraction_log.md             # per-paper log + validator report
05_data_extraction/tidy_estimates.csv            # one row per estimate
05_data_extraction/by_type/<meta_type>.csv       # per-type tidy tables
```

## How to run the validator manually

```bash
python .claude/skills/meta-extraction/scripts/validate_estimates.py \
  --in   05_data_extraction/extraction_candidates.jsonl \
  --out-tidy 05_data_extraction/tidy_estimates.csv \
  --out-by-type-dir 05_data_extraction/by_type \
  --out-report 05_data_extraction/extraction_log.md
```

The validator is dependency-free (Python 3.9 stdlib only). It does NOT do any
extraction; it reads what the agent already wrote, sets `review_status` and
`needs_review_reason`, derives `se` from a symmetric CI when missing, and
rebuilds the per-type CSVs idempotently.

## What this skill deliberately does NOT do

- It does not pool / model / estimate τ². Statistical synthesis is handled by
  `meta-statistics-r` and `diagnostic-meta-analysis`.
- It does not call an LLM. The agent itself reads the paper.
- It does not do Wan/Hozo median→mean conversion. The conversion is done
  downstream after the human review confirms the median/IQR row.
- It does not overwrite `reviewer = user` decisions on rerun. New extractions
  arrive as additional candidates with `supersedes_row_id`.

## Adding a new Meta type later

1. Add `templates/NN_<new_type>.md` mirroring the style of the existing per-type files (row schema, staged search, what to look for, what to avoid, conflict priority, example row).
2. Add the type to the table in `templates/00_paper_type_router.md`.
3. Add the type's effect-measure to `RATIO_MEASURES` or `RAW_MEASURES` in `scripts/validate_estimates.py` if it needs a new measure name.
4. No change to `SKILL.md` is required.
